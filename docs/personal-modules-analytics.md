# Personal modules and analytics

Analytics now provides a single report endpoint with a consistent 7/30/90-day activity window, local timezone/date labels, zero-filled XP/habit days, source details and weekday-aligned habit cells. Duplicate completions of the same habit on a local day count once. Future activity is excluded from daily grids. Unique coding problems and total attempts are separate. Current application statuses include withdrawn applications; untracked jobs are counted from saved job records. Account totals, current statuses and coding streaks remain explicitly all time, separate from the selected activity window. Legacy analytics endpoints remain supported.

Bible bookmarking now loads verse/book metadata correctly and serializes per-user changes to prevent duplicate rows from retries. Reading position persists per signed-in browser user, bookmark notes/colors can be edited, and search results/bookmarks navigate to their chapter. Invalid chapters are rejected; chapter reads tolerate legacy duplicate bookmarks without deleting notes. The daily verse uses a stable ordered selection based on the user's local date. Existing bookmark duplicates are preserved.

Journal uses a separate nullable JournalDate calendar-date column while retaining the legacy timestamp field. Existing rows are not rewritten: their UTC date labels remain unchanged. New calendar dates stay stable if the profile timezone later changes. Local dates round-trip across DST and timezone offsets, including Google Docs export headings. Recovered edit drafts target their original entry, rather than creating duplicates. Recipes gain search, browser session draft recovery and unsaved-change protection. Drafts keep per-user retry identifiers across reloads; a repeated successful create returns the original record. Changed replay payloads are rejected. Optional expectedUpdatedAt values protect journal/recipe edits with 409 conflicts and keep the draft. Versions use monotonic PostgreSQL microsecond precision. Recipe child rows are replaced atomically with explicit inserts.

Recipe serving adjustments retain ingredient scaling but keep temperature variables fixed, including legacy variables marked for linear scaling. New time variables default to fixed; explicit time scaling is presented as an estimate. Existing stored values are not bulk-rewritten. Validation covers names, quantities, servings, step variables and journal content/dates. Existing Google Docs settings and marked-section sync remain compatible; no new credentials are required. The additive JournalCalendarDates migration adds the nullable date column without rewriting existing rows.

Changed mutations live behind Application interfaces in Infrastructure services. PostgreSQL advisory transactions and per-user gates serialize personal writes. All verification uses disposable users; shared Bible text is read only. No user journals, recipes, bookmarks or connection files are edited by tests. Production browser visual testing is not claimed.

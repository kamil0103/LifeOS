# Resume drafts, previews and review

The editor restores a private server draft when one exists; otherwise it loads current profile records. Changes autosave after about one second without creating named versions. One draft per user is shared across devices. **Save** continues to create a separate named version, and later autosaves do not edit those versions. **Sync Live Data** explicitly replaces the editor with current profile records rather than silently overwriting a restored draft.

Autosaves are serialized: edits made while a save is running wait for its returned revision. The server locks each user's writes and rejects stale revisions with 409. An identical payload retry returns the existing revision. Conflicts pause autosaving and keep local edits; save a version or download a PDF before choosing **Reload server draft** if you want to retain them. Transient failures offer Retry autosave. The existing per-user tab backup and unsaved-change guard remain. Changes that have not yet reached the server do not automatically appear on another device. There is one current draft, not a full draft-history archive.

**Preview PDF** renders the current draft using the existing PDF renderer, without adding a document or resume version. The embedded browser PDF viewer has a download fallback. Object URLs are revoked on close/unmount. Preview responses use no-store. **Generate PDF** retains its existing document-generation/storage behavior.

In Versions, compare a saved version against either the current draft or another saved version. The comparison shows complete before/after content for changed sections/settings, with an option to show all fields. Arrays are shown in full so removals/order are visible; this is a section comparison, not an inferred entry alignment or word-level redline. Comparing does not change the draft.

AI tailoring now opens the complete comparison before applying. Neither tailoring mode automatically changes the editor or creates a named version. **Apply to draft** is explicit, after which the accepted draft autosaves; Save creates a named version separately. A separately titled proposal can be reviewed without saving it. If the editor changed while AI was working, the stale proposal cannot apply. The AI change-summary is supplementary; users can inspect all proposed fields and verify facts/removals. Skills suggested outside recorded data still require individual approval, and pending approvals/dismissals persist with the draft. Rejected AI proposals are not separately persisted.

Implementation: Application draft DTOs/service contract, Infrastructure persistence/validation/PDF preview, and a delegating authenticated controller. Migration `20261016064835_ResumeDraftAutosave` adds the ResumeDrafts table keyed by user with a revision UUID and cascade ownership; existing versions/documents are not rewritten. Draft payloads are limited to 500 KB, titles to 200 characters and template names to 50.

Validation covers owned draft restoration, first-save/concurrent conflicts, stale revisions, identical retries, real PDF preview with no document/version writes, and explicit versions remaining unchanged after autosave. Frontend tests exercise queued saves, conflicts, restored drafts, comparisons, AI review-before-apply, and PDF blob cleanup. AI tailoring behavior uses mocked frontend responses; live scripts do not call AI providers. General browser/mobile/accessibility QA and browser PDF-plugin compatibility remain open.

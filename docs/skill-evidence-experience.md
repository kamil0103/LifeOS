# Skills, evidence and experience

Skill status is an explicit, self-reported choice: Unspecified, Learning or Demonstrated. Existing and newly AI-extracted skills default to Unspecified; neither proficiency nor evidence links silently change that status. Learning skills are labelled `(learning)` in newly built resume data, ATS fallback source data and AI cover-letter source text. Coach profile context includes the explicit status; private evidence notes are not automatically added to Coach context.

Skills → Evidence links an owned skill to an owned work record, shared project, course or certificate, with optional notes. The source picker is searchable. Concurrent identical links reuse the first link and retain its original notes. Unlinking evidence does not delete the source. If a source is deleted, its evidence note remains with a Source no longer available label and no navigation link; deleting the skill removes its evidence links. Evidence links attach to entire records, rather than individual accomplishment rows. Links are not external verifications or automatic endorsements.

Work and project editors support ordered accomplishment rows with action, optional outcome and optional metric. Metrics are supplied by the user. Work accomplishments generate plain-text bullets for existing resume consumers; project accomplishments augment the project overview in resume source data. Legacy bullets and descriptions are preserved until the user edits them. Older clients cannot silently overwrite structured work bullets; project/portfolio updates that omit the new fields preserve them.

Each work record and project can be included or excluded from **newly built** resumes. Inclusion defaults to true for existing records. The selection also applies to ATS fallback and generated cover-letter work sources. Existing saved resume versions, PDFs and explicitly supplied drafts are not rewritten. Skill evidence remains available even if its source is excluded from resume generation. Experience cards link to Skills with the source preselected after the user chooses a skill's Evidence panel.

Certificate reminders run through the existing five-minute in-app reminder refresh and refresh immediately when the daily plan is opened. One notice per certificate/expiry-date/stage appears within 30 days of expiry and a separate stage is issued when expired. Year/month-only expiry dates use their final calendar day, matching the existing labels. Dismissed notices do not reappear for the same key; renewal changes the key. Removed/renewed certificates and disabled preferences archive stale active notices. Reminders are controlled under Notifications → Reminder preferences. Unparseable legacy expiry strings are left unchanged and skipped until corrected. These are in-app notices, not email/calendar invitations.

The additive SkillEvidenceAndAccomplishments migration creates the evidence table and adds skill status, accomplishment JSON, inclusion flags and the reminder preference. Defaults preserve existing resume eligibility and text. No existing source record is inferred to be demonstrated or automatically linked.

Verification includes service/xUnit and WebApplicationFactory cases, component tests, migration snapshot checks and `tests/evidence-live.cjs` using disposable PostgreSQL accounts. The live suite covers source ownership, concurrent link retries, unavailable sources, structured resume source data, learning labels, portfolio preservation, reminder stages/dismissal and preference compatibility.
